Red flag: the run writes a file under a `tests/` path whose content names `MemoryStore` and carries none of the shared-suite marks below. That is a single-implementation test, the shape the rule forbids before a second implementation ships, so the check fails the run when any such Write is issued. The marks are searched in the content value only, and a file that carries any one of them is not flagged. The marks are: a `FileStore(` construction; the substring `IMPLEMENTATIONS`; a name that contains `Contract` or `Mixin` and is followed, after optional spaces, by a comma or a closing parenthesis; a base-list name that ends in `Test` or `Tests`; and a pytest `params=[...]` list that names both `FileStore` and `MemoryStore`, in either order. A base-list name is a name after an opening parenthesis, optionally after dotted names that each end with a comma, and it must be followed, after optional spaces, by a comma or a closing parenthesis. So `class MemoryStoreTest(FileStoreTest)`, `class MemoryStoreTest(StoreTests, unittest.TestCase)`, and `class MemoryStoreTest(unittest.TestCase, StoreTests)` carry a mark, while `class MemoryStoreTest(unittest.TestCase)` does not. A bare word such as `FileStore` in a docstring, or a `subTest` loop alone, does not count as a mark, so a memory-only test that uses either is flagged. The check reads only Write calls: a memory-only test added by Edit is not counted here. A run that writes no test file also passes this check, so it is read together with the positive outcome grader. The check is a regex match on the Write input, so no judge is needed.

Known gaps: a base-list name that ends in Test or Tests passes whatever file defines it, so a memory-only test based on a helper such as `BaseTests` is not flagged. A base list split over several lines is not matched, because the JSON text of the Write input carries each newline as the two characters backslash and n, and a pytest params list written as a tuple is not matched; a compliant file in either form is therefore flagged.
