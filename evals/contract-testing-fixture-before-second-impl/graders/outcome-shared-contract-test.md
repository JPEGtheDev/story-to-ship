type: tool_used
tool: Write
input_match: '^(?=[\s\S]*"file_path":"[^"]*/tests/)(?=[\s\S]*"content":"[\s\S]*MemoryStore)(?=[\s\S]*"content":"[\s\S]*(?:FileStore\(|IMPLEMENTATIONS|\w*(?:Contract|Mixin)\w*\s*[,)]|\(\s*(?:[\w.]+\s*,\s*)*\w*Tests?\s*[,)]|params\s*=\s*\[(?=[^\]]*FileStore)(?=[^\]]*MemoryStore)))'
min: 1
---

Behavior: the run writes a file under a `tests/` path whose content names `MemoryStore` and also carries a shared-suite mark. The file path and the content are read separately: `MemoryStore` and the mark are searched in the content value only. The marks are the same as in the never-memory-only-test check: a `FileStore(` construction; the substring `IMPLEMENTATIONS`; a name that contains `Contract` or `Mixin` and is followed, after optional spaces, by a comma or a closing parenthesis; a base-list name that ends in `Test` or `Tests`; and a pytest `params=[...]` list that names both `FileStore` and `MemoryStore`, in either order. A base-list name is a name after an opening parenthesis, optionally after dotted names that each end with a comma, and it must be followed, after optional spaces, by a comma or a closing parenthesis. A bare word such as `FileStore` in a docstring, or a `subTest` loop alone, is not a mark. Both `MemoryStore` and a mark must sit in the same Write, so a separate contract mixin that does not name `MemoryStore` does not pass on its own. A file that carries a mark passes; for example, a test class based on `FileStoreTest` or `StoreTests`, a class that mixes in a shared contract, or a parameter list that names both store classes. The check is a regex match on the Write input, so no judge is needed.

Limits: the check reads only Write calls. An Edit that turns `tests/test_file_store.py` into a suite over both stores is a compliant route that this grader does not count, so a run that takes that route scores FAIL here. The check does not confirm that the file is run, that the mark is used correctly, or that the suite exists before the second implementation: the call order is not checked, although the case name says "before second impl".

Known gaps: a base-list name that ends in Test or Tests passes whatever file defines it, so a memory-only test based on a helper such as `BaseTests` passes. A base list split over several lines is not matched, and a pytest params list written as a tuple is not matched; a compliant file in either form scores FAIL.
