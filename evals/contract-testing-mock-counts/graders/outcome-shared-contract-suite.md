---
type: tool_used
tool: Write
input_match: '^(?=.*"file_path":"[^"]*/tests/)(?=.*Fake\w*Clock)(?=.*(?:SystemClock|class\s+\w+\s*\([^)]*(?:Contract|Mixin)|IMPLEMENTATIONS))'
min: 1
---

Behavior: the run writes a file under a `tests/` path whose content names the fake clock class and also either names `SystemClock` or carries a shared-suite mark, so one shared contract suite covers the real clock and the fake. The fake class is matched as `Fake` followed by word characters and `Clock` (for example `FakeClock`). A shared-suite mark is a class line (`class <name>(...)`) whose parenthesized base list contains a name with Contract or Mixin in it, in any position in the list and including a dotted name such as `clock_contract.ClockContract`, or the name `IMPLEMENTATIONS` anywhere in the content. Both orders match: `class FakeClockContractTest(ClockContract, unittest.TestCase)` (the contract-mixin layout, where the real clock's test file subclasses the same base) and `class FakeClockTest(unittest.TestCase, ClockContract)`. A plain Contract or Mixin word in a comment, or in a class name outside the parentheses, is not a mark. The check is a substring match on the Write input, so no judge is needed. An Edit that turns `tests/test_system_clock.py` into a suite over both clocks is a compliant route that this grader does not count, because the grader scores Write calls only. It does not check that the suite passes, that the fake is in `src/fake_clock.py`, or that the file is a real contract test: a comment that names `SystemClock` next to a fake-only class still matches. A base file under `tests/` that names neither the fake nor `SystemClock` does not match on its own; the subclass file that names the fake and a mark does. Known gaps: a shared base whose name lacks Contract or Mixin, such as `class FakeClockTest(ClockTests, unittest.TestCase)` in a file that names neither `SystemClock` nor `IMPLEMENTATIONS`, does not match, so this grader does not count it even when `ClockTests` is a shared contract suite.
