min: 1

Behavior: the run issues at least one Bash command that runs the shared contract test runner. A command counts when it contains `-m unittest` or `-m pytest` (for example `python3 -m unittest discover -s tests -t .`), or when `pytest` is a command word: at the start of the command, optionally after `uv run` (for example `uv run pytest`), or after `;`, `&`, `|`, `(`, or a line break (for example `cd repo && pytest tests`). A word that is not a command word, such as `echo pytest`, does not count. A probe flag directly after `pytest`, `-m unittest`, or `-m pytest` makes the command not count; the probe flags are `--version`, `-V`, `--help`, `-h`, `--collect-only`, and `--co` (for example `pytest --version`, `python3 -m pytest --version`, `python3 -m unittest -h`). `pip install pytest` and `grep -n unittest ...` do not match. A direct run of a test file, such as `python3 tests/test_store_contract.py`, `python3 ./tests/test_store_contract.py`, or the same file by absolute path, does not count. A bare `python3 tests/test_store_contract.py` fails at import from the repo root (ModuleNotFoundError: No module named 'src') and runs no test. A command that contains the word `mktemp` anywhere, or that contains `cp` directly followed by a flag with an `r`, `R`, or `a` in it (for example `cp -r`, `cp -R`, `cp -a`, `cp -av`), or by `--recursive` or `--archive`, does not count, even when `mktemp` only names a log file (for example `python3 -m unittest discover 2>&1 | tee $(mktemp)`).

Known gaps: a command with `mktemp`, or with the `cp` flags above, is not counted even when it also runs the suite in the repo (for example `cp -r docs /tmp/d && python3 -m unittest discover -s tests -t .`). A direct run of a test file with PYTHONPATH set (for example `PYTHONPATH=. python3 tests/test_store_contract.py`) is not counted, although it runs the file.

Limitation: the scorer checks only that a runner command exists. It cannot order calls, so it cannot tell that the run came after the new implementation was added, and it does not check that the new implementation was registered (the outcome grader covers the registration). A baseline run made before the implementation exists is also counted. A runner started in a temporary directory without `cp` or `mktemp` in the same command is also counted. The check does not check that the tests passed. It is a regex match on the Bash `command` value, so no judge is needed.
