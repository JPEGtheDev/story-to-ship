Pass: the session holds at least one Bash call whose command (the "command" field of the tool input, not the description) runs grep over the written instructions file (any name the run chose; plan.md and anything under src/ are excluded, as in sweep-grep-issue-refs) and whose grep tests for non-ASCII characters. The case's allowed_tools list omits the Grep tool, so the search has to be a Bash grep; a search through another tool does not count. Assumptions: the trace is compact JSON, so a backslash in the command appears doubled in the JSON text and a double quote inside the command appears escaped. A literal non-ASCII character appears raw in the JSON text only when the harness JSON is unescaped (assumed; not checked against the harness), and the JSON \uXXXX escape of the same character is accepted too. The grep's test must be one of these forms, quoted with single or double quotes, or unquoted:
- a negated class whose content holds a range that ends at 0x7F, 0x7E or a tilde: [^\x00-\x7F], [^\x{00}-\x{7F}], [^\0-\177], [^ -~], [^\t -~], [^\x09\x0A\x20-\x7E], [^\t\x20-\x7e];
- a negated class holding [:print:] or [:ascii:] (for example [^[:print:]] or [^[:ascii:]]), or the negated Unicode property [^\p{ASCII}];
- the Unicode property \P{ASCII}; a class on the 0x80 to 0xFF range (for example [\x80-\xFF]) or on the octal range \200-\377; or a literal non-ASCII character;
- an anchored inverted match such as grep -v '^[\x00-\x7F]*$' (a -v with a class that holds the 0x7F, 0x7E or tilde range, anchored with ^ and *$).
Not accepted: a positive printable or ASCII class ([[:print:]], [\x00-\x7F], [ -~]) matches ASCII lines, and grep -axv '.*' prints nothing for a line that holds a non-ASCII character, so neither proves the check. The grep must start a command (after a semicolon, ampersand, pipe, opening parenthesis, backtick, newline, or leading VAR=value words). Its test must come before the grep's arguments end, which happens at an unquoted semicolon, ampersand, pipe, # comment, < or > (a # inside a quoted pattern is part of the pattern). The grep's arguments stop at the closing quote of the command field, so a non-ASCII character in the description does not count, and a command containing a heredoc or here-string does not count. Pass examples: "LC_ALL=C grep -nP '[^\\x00-\\x7F]' brief.md", "LC_ALL=C grep -nP \"[^\\x00-\\x7F]\" todo1-brief.md", "grep -nP '[^\\x{00}-\\x{7F}]' brief.md", "LC_ALL=C grep -n '[^ -~]' todo1-brief.md", "grep -nP '[^[:print:]]' brief.md", "grep -nvP '^[\\x00-\\x7F]*$' brief.md". Fail: no Bash call runs grep with a non-ASCII test over the written file, for example when the run only searches for issue references, when its only grep over the brief uses a plain ASCII pattern such as "grep -n issue brief.md" or "grep -n x86 brief.md", when a positive printable class is the only test ("grep -c '[[:print:]]' brief.md"), when the non-ASCII test is written only in a description field, when the only such grep targets plan.md or src/, or when the test sits only inside a heredoc that writes the file. Limitation: the match is a regex over the command text, so a non-ASCII check run through a tool other than grep does not count, and the grader cannot tell whether the search's output was reported; the process grader covers that.
