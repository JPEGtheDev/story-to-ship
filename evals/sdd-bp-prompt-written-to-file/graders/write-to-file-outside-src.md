---
type: regex
pattern: '"name"\s*:\s*"Write"(?:(?!\}|"name"\s*:\s*")[\s\S])*?"file_path"\s*:\s*"(?!(?:[^"]*/)?(?:src|\.git)/)[^"]+"|"name"\s*:\s*"Edit"(?=(?:(?!\}|"name"\s*:\s*")[\s\S])*?"old_string"\s*:\s*""(?=\s*[,}]))(?:(?!\}|"name"\s*:\s*")[\s\S])*?"file_path"\s*:\s*"(?!(?:[^"]*/)?(?:src|\.git)/)[^"]+"|"name"\s*:\s*"Bash"(?:(?!\}|"name"\s*:\s*")[\s\S])*?"command"\s*:\s*"(?:[^"\\]|\\.)*?(?:\s>>?|\btee(?:\s+--?[A-Za-z][\w-]*)*\s)\s*"?(?!-|&|>|/dev/null(?![^\s"])|(?:[^\s"]*/)?(?:src|\.git)/)[^\s"]+'
match: contains
target: trace
---

Behavior: the run saves text to a file outside src/, so the instructions for the helper live on disk and the run does not rely on a one-line message alone. A file write counts in three forms. First, a Write call whose file_path is outside src/ and outside .git/. Second, an Edit call that creates the file: its old_string is the empty string (a creating Edit carries old_string as an empty value), and its file_path is outside src/ and outside .git/. An Edit whose old_string is not empty changes a file that already exists and does not count, whatever its file_path. Third, a Bash command that writes a path with a redirect (> or >>), a tee (with or without a flag such as -a or --append), or a heredoc or printf sent into one of those. The Bash branch reads the command string of each Bash call, with JSON-escaped quotes read as quotes, so a double-quoted echo or printf counts. It passes on a redirect or tee whose target is not /dev/null, not a file descriptor (>&), not a bare flag such as the -a of tee, and not under src/ or .git/. The Write and Edit branches read the file_path value and pass when that path has no src/ or .git/ directory segment, either at the start of the path or after a slash. A path such as src-notes/ or docs/src.md does not count as src/. The Edit branch reads the old_string and file_path keys of one call in either order.

Pass: the trace holds at least one such file write outside src/ and .git/. Fail: the run makes no file write (no Write call with a file_path outside src/ and .git/, no Edit call with an empty old_string and a file_path outside src/ and .git/, and no Bash redirect or tee into a path outside src/ or .git/), or every write targets a path under src/ or .git/. The check is a regular-expression match on the trace text, so no judge is needed. It does not check the content of the file or its order against the Agent call; the two llm graders beside it cover those.

Assumptions and limits: the trace is compact JSON, a tool call's name is written before its input, and a Bash command appears as a command string. The check cannot tell a runner write from a helper write, so a helper's Write outside src/ also passes (the trace may or may not hold helper calls). A space before a > in quoted prose inside a Bash command also passes the Bash branch without a file write; the llm graders on the same case rule on content. A write under src/ made with Bash is not caught here; the never grader covers Write and Edit only. A redirect with no space before the > (for example x>/tmp/p.md) is not matched by the Bash branch.
