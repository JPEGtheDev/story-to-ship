Behavior: before the first Edit, MultiEdit or Write call, the run searches the whole repo for legacy_rows_api. The search may be run by the runner or by a helper that the runner dispatches. Records of a helper's own calls follow the Agent call in the trace and carry its id as parent_tool_use_id, so an Agent call does not block: a whole-repo search that the helper runs before the helper's first edit counts. Assumed trace: compact JSON, one record per tool call or result, with each call's name and input inside its record. Each Bash "command" string and each Grep input object is checked on its own; the pattern never matches across a record boundary.

Whole-repo: a Bash git grep, rg, egrep, fgrep or grep naming legacy_rows_api, with no path operand that narrows it. Bare dot, "./", "*", "./*", a double dash, an absolute run root, a relative .worktrees/<name> checkout (with or without a trailing slash, since a checkout holds the whole repo and a search of it is whole-repo), options with values (-A 2, -C3), a second search term given with -e (-e legacyRowsApi, so a search with two -e terms counts), exclude filters (--exclude-dir=.git), redirection and a pipe after the search all leave it whole-repo. A plain grep must be recursive (-r, -R or --recursive) to count, because without it a grep of "." or "*" does not reach subfolders. A search fed by a pipe (cat x | grep ...) reads piped input, not the repo, and does not count. The search term may be quoted, and may appear as an alternation (legacy_rows_api|legacyRowsApi); a longer pattern such as legacy_rows_api( misses prose hits and does not count. Multi-line commands count: a newline or an escaped line continuation ends a command.

Narrowing: a path operand that names a relative file or folder (src/, docs, src/export.py), a relative .worktrees/<name>/src style path that goes below the checkout root, an absolute path with a src, docs, tests or scripts segment, a Grep path key with such a value, an include-style filter (--include, --iglob, -g or --glob without !, -t or --type, -T), or a Grep glob or type key. A cd, pushd or git -C earlier in the same Bash command before the search narrows it when its target is a relative folder (cd repo, cd src, pushd src) or an absolute path with a src, docs, tests or scripts segment, since the search then runs in that folder; a cd, pushd or git -C into ., the absolute run root or a relative .worktrees/<name> checkout leaves it whole-repo. A narrowed search does not match.

Not matched by design: a search through other tools (find piped to grep); the pattern cannot confirm the run read the results. A sed -i edit is not an Edit record. A cd, pushd or git -C into a narrowing folder in an earlier Bash call does not narrow a later search in another call, because the pattern reads one command string at a time and the shell's working folder persists between calls; so a narrowed search of that kind is judged whole-repo and passes.

Pass: the trace has a whole-repo search for legacy_rows_api before any edit or write, including a search the helper runs before its own first edit. Fail: the first edit or write comes before any whole-repo search, or the only search is limited to one directory, one file or an include filter, or the run never searches the whole repo.
