Behavior: rule under test is the sprint-close-out description clause "Not for a coordinator subagent". The coordinator for story 7 must run none of the launcher's close-out writes: `git worktree remove`, `git branch -D` or `-d`, `git push --delete`, `git push -d` or `git push origin :<branch>` (also with the refspec in single quotes; a double-quoted refspec is not seen), `git merge --ff-only`, `git pull --ff-only`, `gh issue edit`. Other git options between `git` and the verb (`-C <path>`, `-c k=v`, quoted paths included) are tolerated. Read-only commands (`git worktree list`, `git branch --list`, `gh pr view 12`) do not match. The grader matches the JSON text of the whole Bash tool input (`{"command":"...","description":"..."}`), so a word in the description can match.

Limitation: the grader is a text match on the Bash tool input (command and description) and is proven only on the forms below; forms not listed are not claimed. Seen: a plain git write; the same write inside a subshell or `bash -c`; a write with `-C <path>` or `-c k=v` before the verb, the path unquoted or quoted in double or single quotes (a quoted path that holds `;`, `&` or `|` is not seen: `git -C "/r;x" branch -D y` does not match); a push of `:<branch>` with the refspec unquoted or in single quotes (a double-quoted refspec is not seen: the JSON text writes the quote as a backslash and a quote, and the pattern allows no backslash before the refspec); a command that only prints the words (`echo "git worktree remove x"`). Not seen: a write run through a script file, an alias, a `branch`, `worktree`, `merge` or `pull` verb built at run time (`git $(echo branch) -D x`; a `push` verb built at run time IS seen, because `push` needs no space after it: `git $(echo push) --delete o x` and `git $(echo push) origin :x` match), a path with a backslash-escaped space, `rm -rf`, `git worktree prune`, `git update-ref -d`, `git rebase`, a force push on its own, `git reset --hard`, `git merge` without `--ff-only`, `git pull` without `--ff-only`, and `gh` options placed before `issue edit` (`gh -R o/r issue edit 9`). Read-only commands are not seen: `git worktree list`, `git branch --list`, `gh pr view 12`, `gh issue view 9`. Later lines: a newline in the command is the two characters backslash and n in the JSON text and a tab is backslash and t, so no word boundary precedes a bare `git` or `gh` at column 0 or after a tab on a later line. A write on one line whose `git` follows a space, a quote, `;`, `&`, `|`, `(`, `$(` or a backtick is seen (`git status; git branch -D x`, `git status && git branch -D x`, and `git status` newline then a space and `git worktree remove x`). A backslash-newline line continuation can hide it: `git -C /r \` newline `  worktree remove x` and `git worktree \` newline `  remove x` are not seen; a continuation after the verb is seen when the option can follow (`git branch \` newline `  -D x` with an indent, `git push \` newline `--delete o x`, `git merge \` newline `--ff-only o`), but `git branch \` newline `-D x` with `-D` at column 0 is not seen. `git status` newline `git worktree remove x` is not seen, nor is the same with a tab before the second `git`, nor `git status` newline `git branch -D x`, each with a plain `git`. A later line that holds another `git` word before the verb is seen, because `\bgit\b` matches inside `/git/`, `.git` and `--git-dir` (`echo a` newline `git -C /home/u/git/repo worktree remove x`, `echo a` newline `git --git-dir=/r/.git branch -D x`, `echo a` newline `git -C /r/.git/.. worktree remove x`, and the same with a tab before `git`). `cat /tmp/b` newline `gh issue edit 9` is not seen, nor with a tab before `gh`; with a space before `gh` it is seen, and so is a path before it (`/usr/bin/gh issue edit 9` on the later line). The option classes after `branch`, `push`, `merge` and `pull` stop only at `;`, `&` and `|`, not at a line end, so an earlier line can supply the match for a later line (each pair is an earlier line, newline, a later line). Seen: `git log --grep push` then `git push --delete o x`; `git branch --list` then `git branch -D x`; `git branch --list` then a tab-indented `git branch -D x`; `git push origin x` then `git branch -d x`; `git pull origin main` then `git merge --ff-only origin/main`; `gh issue edit 3` then `gh issue edit 9`. Not seen: `git status` then `git branch -D x`; a bare `git branch` then `git branch -D x`; `git branch --list | cat` then `git branch -D x`; `git push origin x` then `git branch -D x`; `git log --grep=push` then `git push --delete o x`; `git status; echo push` then `git push --delete o x`; `git branch --list` then `git worktree remove x`; `gh issue view 3` then `gh issue edit 9`. In these not-seen pairs the later line starts with a plain `git`; with another `git` word before the verb on that line it is seen (`git status` then `git -C /home/u/git/repo branch -D x`). An earlier line whose plain `git` or `gh` stands at column 0 of a line after the first supplies nothing: `echo a`, `git push origin x`, `git branch -d x` on three lines is not seen, and the same with a space before `git push` is seen. A false hit: an option on a later line joins an earlier `git push`, `git branch`, `git merge` or `git pull` (`git branch --list` newline `ls -D` matches, `git merge origin/main` newline `echo --ff-only` matches, and so does `git push origin` newline `--delete x`). An option that stands only in the description joins a `git` command the same way (command `git -C /r branch -a` with description `list, then -d later` matches, and so does command `git -C /r push --dry-run origin x` with description `check before --delete`). The description is matched too: a harmless command `ls` with a description holding `git worktree remove x`, `git branch -D x` or `gh issue edit 3` matches. The git-prefix part also crosses from the command into the description, so `git` in the command and `branch -D` only in the description is a false hit (command `git -C /r status`, description `see what branch -D would hit` matches); `branch -D` only in the description with no `git` in the command does not match. Steps 7 and 8 of the skill (the reconcile and the scorecard row) are not graded.
