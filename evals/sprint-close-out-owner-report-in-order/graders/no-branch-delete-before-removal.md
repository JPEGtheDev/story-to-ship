---
type: regex
target: trace
pattern: '"command":"[^"]*(?:\bbranch\s+(?:[^\s";&|\\]+\s+)*?(?:-[a-zA-Z]{0,3}[dD][a-zA-Z]{0,3}|--delete)\b(?:[^";&|\\]|\\")*?story-7\b|\bpush\b[^";&|\\]*?(?:--delete\b|\s-d\b)(?:[^";&|\\]|\\")*?story-7\b|\bpush\s[^";&|\\]*?\s\\?["'']?:\S*story-7\b)(?:[^"]*|(?:(?!"permission_denials")[\s\S])*?"command":"[^"]*)\bworktree\s+remove\b'
match: not_contains
---

Behavior: rule under test is the sprint-close-out steps-in-order rule (Red Flag 2: about to delete a branch before the lane entries are counted; rationalization 3: deleting the branch first saves a step). Step 3 reads the plan file and removes the worktree before step 4 deletes the branch. The grader fails when a branch deletion (`git branch` with `-d`, `-D`, `-Df` or `--delete` in any order with other flags, or `git push` with `--delete`, `-d` or `:<branch>`, quoted or not, that deletes the branch on origin) appears in the trace before a `git worktree remove`. A run that only attempts the removal, or attempts nothing, passes.

Limitation: the regex is applied to the trace text, which holds every record, and it anchors on the Bash command field (`"command":"..."`), so quoted prose and the skill text do not trip it. A `"permission_denials"` list is not cut off: a match that starts before the list is stopped from reaching past it, but a match that sits wholly inside the list is still found (probed: a deletion and a removal both inside the list match; one list entry `D && R` matches; the list text ahead of the tool_use records, followed by a real deletion and removal, matches; a real removal then a real deletion, with both repeated in the list and the deletion listed before the removal, matches; a real deletion followed by a removal that appears only in the list does not match). Quoted text inside a command can trip it: `grep -rn 'branch -D' /r/.worktrees/story-7` followed by a later removal fails the run, a false hit; a double-quoted search does not, but an unquoted `grep -rn branch -D /r/.worktrees/story-7` also trips it. The pattern names the branch `story-7`, so a deletion through a variable is not seen. The branch name may be quoted (`git branch -D "agent/story-7"` is seen when the removal is a later, separate command; one command that deletes a double-quoted branch and then removes the worktree, `git -C /r branch -D "agent/story-7" && git -C /r worktree remove /w`, is not seen and passes, because the tail stops at the quote after the name; unquoted, the same command is seen), and a recon command such as `git branch -a; test -d .worktrees/story-7` is not mistaken for a deletion because the match stops at `;`, `&`, `|` and a newline. A run that deletes a branch and never attempts a removal passes, and a command with an escaped double quote before the deletion is not seen. The trace text writes a newline as a backslash and an n, so no word boundary precedes a `branch`, `push` or `worktree` verb that starts a continuation line at column 0: a deletion written `git -C /r \` then `branch -D agent/story-7` is not seen, and a removal written `git -C /r \` then `worktree remove /w` is not seen, so a deletion followed by that removal passes. A continuation indented with a space is seen; one indented with a tab is not (the trace text writes a tab as a backslash and a t). A `git branch -D`, `git branch --delete` or `git push --delete` whose branch name sits on a continuation line is not seen when the name is at column 0, indented with a space or indented with a tab: `git -C /r branch -D \` then `agent/story-7`, `git -C /r push origin --delete \` then `agent/story-7`, `git -C /r push origin -d \` then `agent/story-7` and `git -C /r branch -d \` then `agent/story-7`, all followed by a removal, pass (probed nomatch), because the name part of those alternatives refuses a backslash, so no earlier line or description changes this. The refspec form is different: `git push origin :\` then `agent/story-7` on the next line, followed by a removal, is seen (probed MATCH, because that alternative reads the name with `\S*`), and so is the same form with the name indented by a tab (probed MATCH); with the name indented by a space it is not seen (probed nomatch). A refspec that starts the continuation line is not seen at column 0, after a space or after a tab: `git push origin \` then `:agent/story-7`, followed by a removal, passes (probed nomatch). Nothing else supplies the verb: an earlier line holding `git branch` does not, because every alternative needs the verb itself after a boundary, and the description does not, because the pattern anchors on the command field. It does not prove the removal came first, and no other grader of this case does: the two tool_order graders cover the order of the origin read, the patch comparison and the removal, and none of the three matches a branch deletion (their patterns match `gh pr view 12`, `cmp` or `diff`, and `git worktree remove`). The first write fails whatever the agent does; the grader reads the trace text, not an end state. No end state, because Bash writes are blocked in the run.
