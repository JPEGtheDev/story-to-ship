---
type: tool_order
before:
  tool: Bash
  input_match: '\bcmp\b|\bdiff\b[^\n;&|]*<\([^\n]*<\('
after:
  tool: Bash
  input_match: '\bgit\b[^\n]*\bworktree\s+remove\b'
---

Behavior: rule under test is the sprint-close-out steps-in-order rule (Iron Law, BEFORE PROCEEDING item 2, rationalization 2: the patch comparison is not a formality). Step 2 compares the patches before step 3 removes the runner worktree. The first patch comparison must come before the first `git worktree remove` attempt.

Limitation: it grades steps 2 and 3 only. It fails if the agent never attempts the worktree removal (for example it stops after a failed read), so a run that stops early scores 0 here; the origin-read grader and the reply grader still tell that story. A single chained command counts as one position. A patch comparison written as two plain `git diff` calls, or made with `git range-diff` or `git patch-id`, is not counted unless it is wrapped in `cmp` or `diff <(...) <(...)` (`diff <(git diff a b | git patch-id) <(git show S | git patch-id)` is counted), and the `git diff --numstat` lane count is not mistaken for a comparison. Both patterns run on the JSON text of the whole Bash tool input (command and description), so a word in the description can match: `git -C /r worktree list` with description "before worktree remove" counts as a removal attempt, and `git diff --numstat a b` with description "compare with cmp" counts as a comparison. A newline in the command is the two characters backslash and n there, so `[^\n]` in the removal pattern crosses lines (`git status` then `echo worktree remove` on the next line matches), and no word boundary precedes a `cmp`, `diff` or `git` at column 0 of a line after the first (`\ncmp` reads `ncmp`, `\ngit` reads `ngit`), so such a word is not seen on its own. A line indented with a space is seen; a line indented with a tab is not (the JSON text writes a tab as a backslash and a t). The miss holds only when nothing else in the input supplies the match: the description can supply it, and an earlier line that holds a match of its own counts. For the comparison, a `diff <(..) <(..)` after an earlier `diff` line is seen, as in the origin-read grader. For the removal, an earlier line holding a `git` supplies it, because the `[^\n]*` tail runs on past the backslash and n (`git status` newline `git worktree remove x` matches, with or without a `;` ending the first line, and so does a tab-indented second line). A `worktree remove` that starts a continuation line at column 0 or after a tab (`git -C /r \` then `worktree remove /w`) is not seen even then, because the word `worktree` has no boundary before it; a continuation indented with a space is seen. No end state, because Bash writes are blocked in the run.
