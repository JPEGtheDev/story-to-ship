---
type: tool_used
tool: Bash
input_match: '\bcmp\b|\bdiff\b[^\n;&|]*<\([^\n]*<\(|\bdiff\s+(?:-\S+\s+)*(?:\S*/tmp/\S*|\S*\.patch)\s+(?:\S*/tmp/\S*|\S*\.patch)\b'
min: 1
---

Behavior: rule under test is sprint-close-out step 2 ("A difference goes to the owner; do not continue"). The run must compare the patch of the squash commit with the patch of the runner branch tip: any command text holding the word `cmp` (it does not check what is compared or that `cmp` is the command: `grep cmp file` and `echo cmp` pass, and so does a description holding `cmp`), or `diff` of two process substitutions, or `diff` of two paths that each contain `/tmp/` or end in `.patch`. Writing a single patch to a file, or reading one with `git diff`, does not count. The grader matches the JSON text of the whole Bash tool input (command and description), so a word in the description can match.

Limitation: it does not check which commits were compared. A `cmp` or `diff` that starts a later line of a multi-line command, at column 0, is not seen unless something else in the input supplies the match, because the JSON text writes the newline as a backslash and an n, so there is no word boundary before it (`echo a` newline `cmp a b` does not match; a line indented with a space is seen, a line indented with a tab is not seen because the JSON text writes a tab as a backslash and a t; a description that holds `cmp` supplies the match, and so does an earlier `cmp` line that is itself seen (the first line, or after a space); for a `diff` of two process substitutions, an earlier `diff` line with no `;`, `&` or `|` after it also supplies the match when that `diff` is itself seen (as the first line, or after a space), because the tail runs on past the backslash and n (`diff <(a)` newline `diff <(b) <(c)` matches; `echo a`, `diff <(a)`, `diff <(b) <(c)` on three lines at column 0 does not), but for a `diff` of two paths it does not, unless the earlier `diff` itself ends in a single `/tmp/` operand: `diff x y` newline `diff /tmp/a /tmp/b` does not match; `diff -u /tmp/x` newline `diff /tmp/a /tmp/b` matches). After the first `<(` of a `diff`, the second `<(` may come after a `;`, `&` or `|`, on a later line (a newline is backslash and n in the JSON text) or in the description: `diff <(git diff a); echo <(b)` matches. Two separate `git diff` reads are not seen; a `diff` of two process substitutions or of two paths that each contain `/tmp/` or end in `.patch` counts whatever they hold, patch or not (`diff /home/u/tmp/a /home/u/tmp/b` matches); nothing is claimed about a `diff` of other files. These real comparisons are not counted: stdin as one operand (`git -C /r diff B H | diff - <(git -C /r diff S^ S)`), a process substitution against a file (`diff <(...) /tmp/s.patch`) and `diff "$A" "$B"` on variables, so a run that does that fails this grader though it did the work. The gh command is a local stand-in that answers MERGED. Every earlier-line form in this file assumes the earlier line is itself seen, as the first line or after a space; an earlier line whose needed word (the `git`, `gh`, `cmp`, `diff` or `rm` of that form) stands at column 0 of a line after the first is not seen and supplies nothing by itself, while the same word later in that line, after a space, is seen. No end state, because Bash writes are blocked in the run.
