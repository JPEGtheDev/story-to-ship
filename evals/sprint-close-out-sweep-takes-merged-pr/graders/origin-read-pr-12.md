Behavior: rule under test is the sprint-close-out start rule (description: the close-out starts when a sweep of origin finds a merged sprint pull request, as well as when the owner reports one; Iron Law: confirm the merge on origin). The sweep reads origin state for PR 12 at least once: `gh pr view` naming 12 (any flags, any repo option), any `gh pr list` command, or `gh pr view` inside a loop over numbers that include 12 (`; do` on the loop line).

Limitation: The grader matches the JSON text of the whole Bash tool input (command and description), not the command alone, so a word in the description can match; a newline in the command is the two characters backslash and n there, so `[^\n]` does not stop at a line end, and the first word of a later line at column 0 has no word boundary before it (`\ngit` reads `ngit`), so `\bgh` misses it there when nothing earlier in the input supplies the match (after an earlier line that holds a `gh`, such as a first `gh pr view 13 --json state` or a `gh auth status` (neither matches alone), the match starts at that earlier `gh`, the tail runs on past the backslash-n and the later line is covered too; an indented line is seen). Any `gh pr list` command counts, whatever it lists or filters, and a loop counts when its number list includes 12, `; do` follows on the same line and a `gh pr view` stands anywhere later in the input text. Reading only PR 13 can pass: `gh pr view 13` with description "Check PR 13 after PR 12" matches, and so does `gh pr view 13` followed on the next line by `echo 12`; `gh pr view 13` alone does not. A non-gh command whose description says "gh pr view 12" also matches. A list command that never reaches PR 12 is not told apart. A loop with `do` on its own line is not seen unless the description also names 12 (then the `gh pr view` in the command matches through it, but only when no `;`, `&` or `|` follows that `gh pr view` in the command); a loop written across several statements or through a variable list, or a `gh` at column 0 of a later line when nothing earlier in the input supplies the match, is not seen. `gh api` reads of PR 12 (`gh api repos/o/r/pulls/12`) do not count. It does not check that the answer was used. The gh command is a local stand-in that answers MERGED for 12. No end state, because Bash writes are blocked in the run.
