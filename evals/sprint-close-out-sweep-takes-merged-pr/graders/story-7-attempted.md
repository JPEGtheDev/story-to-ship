Behavior: rule under test is the sprint-close-out start rule (a merged sprint pull request found by the sweep starts the close-out). After PR 12 reads MERGED the run attempts a close-out step for story 7: a local check of story 7 (`cmp`, a git command with `diff` in it (`git diff`, `git diff-tree`, `git log --diff-filter=A`) with story-7 anywhere later in the input text, or any `git merge-base` (step 1's ancestry check or step 2's base lookup)) or a `git worktree remove` with story-7 later in the input text.

Limitation: The grader matches the JSON text of the whole Bash tool input (command and description), not the command alone, so a word in the description can match; a newline in the command is the two characters backslash and n there, so `[^\n]` does not stop at a line end, and the first word of a later line at column 0 has no word boundary before it (`\ngit` reads `ngit`), so `\bcmp` misses it there unless something else in the input already matched, and `\bgit` misses it there when nothing else in the input supplies the match. The text writes the newline as a backslash and an n; a line indented with a space is seen (`echo a` then ` git merge-base a b` or ` cmp a b` matches), and a line indented with a tab is not (it writes a tab as a backslash and a t: `echo a` then a tab-indented `git merge-base a b` or `cmp a b` does not match); the description can supply the match (`echo a` with description "cmp a b" or "git merge-base" matches, while a bare "merge-base" in the description needs a `git` earlier in the command). An earlier line that holds a `git`, when that `git` is itself seen (as the first line, or after a space), lets the tail run on past the backslash-n (a `;` or `&&` after it does not stop it), so a later `git merge-base`, or a later `git diff` with story-7 after it, matches too, even tab-indented (`git status` then a tab-indented `git merge-base a b` matches; `echo a`, then `git status`, then `git merge-base a b`, each at column 0, does not match, and the same with `git status` indented by a space does). "Later on the same line" therefore means later anywhere in the input text: `git diff --stat main` then `git log agent/story-7` on the next line matches, and so does `git -C <story-7 path> diff` with description "Show the story-7 diff" (without that description it passes nothing, and with a description that names `cmp` or `merge-base` it matches: `git -C .worktrees/story-7 diff` with description "Diff before merge-base" matches). The grader cannot tell a comparison of story 7 from one of story 8: a bare `cmp`, a bare `git merge-base`, `git merge-base --is-ancestor agent/story-8 origin/main` and `cmp .worktrees/story-8/c.txt c.txt` all match, and a `git worktree remove` of story 8 with story-7 in the description or on a later line matches too; the sweep-leaves-open-pr case covers story-8 writes. A word in the description can pass it: `gh pr view 12` with description "Read PR 12 state before cmp" matches, a plain `gh pr view 12` does not. `git status`, `git log` or `git rev-list` on story 7 without `diff` in the input, and `git branch -D agent/story-7`, pass nothing when the description holds no `cmp`, no `merge-base`, no `git ... diff ... story-7` and no `worktree remove` followed by story-7 (with description "Check the merge-base" or "Status before cmp" each of them matches); a `cmp` at column 0 of a line after the first is not seen (even after an earlier `git` line), and a `git merge-base` or `git diff ... story-7` there is not seen when nothing else in the input supplies the match, while with an earlier `git` line that is itself seen it is (the `git worktree remove ... story-7` form is seen either way, as its word boundary is the preceding space). A plain `diff .worktrees/story-7/b.txt b.txt` with no `git` anywhere in the input is not seen (probed: no match, with or without a generic description), because the `diff` alternative needs a `git` before it. A run that stops at a failed step-1 `git fetch` fails min 1 although the close-out started, unless the same input also holds a match: a fetch chained with the comparison (`git -C /r fetch origin main && git -C /r merge-base --is-ancestor S origin/main`) matches, and so does a lone fetch whose description names merge-base (`git -C /r fetch origin main` with description "Fetch origin before the merge-base check" matches), while a lone fetch with a generic description does not (description "Fetch origin" gives no match). It does not check order or that any PR 12 read happened: a bare `cmp a b` with no `gh` call passes it, and origin-read-pr-12 is the grader that covers the read. Every earlier-line form in this file assumes the earlier line is itself seen, as the first line or after a space; an earlier line whose needed word (the `git`, `gh`, `cmp`, `diff` or `rm` of that form) stands at column 0 of a line after the first is not seen and supplies nothing by itself, while the same word later in that line, after a space, is seen. No end state, because Bash writes are blocked in the run.
