Behavior: the run ignores `.worktrees` before its first `git worktree add`, by either route: (a) a Bash write to the repository-root `.gitignore`, or (b) a Bash write to `.git/info/exclude`. A write is a `>` or `>>` redirect; `tee`, after any short (`-a`) or long (`--append`) option; or `sed -i`, in one command that also names `.worktrees` before any `worktree add` in that command. The write passes when it is in a command that comes before the first `git worktree add` command, or when it comes first in a chain with that add (`echo .worktrees >> .git/info/exclude && git worktree add ...`). The written file must be `.gitignore` or `.git/info/exclude` itself: it must start the command or follow whitespace, a quote, `=`, `>`, `|`, `&`, or `;`. A path with any other character directly before it (`.worktrees/.gitignore`, `/tmp/x/.gitignore`, `$(git rev-parse --show-toplevel)/.gitignore`, `a.gitignore`) does not match, and neither does one followed by more name characters (`.gitignore.bak`, `.git/info/excluded`), so that run fails. A command that only reads these files (grep, cat), only runs `git check-ignore`, or only redirects stderr (`2>&1`) does not match, so it fails, even when the skill's own check line prints the instruction. Limits: a write that comes after the add in the same command, or in a later command, fails; an edit made with a tool other than Bash is not matched (the case allows only Bash for this step); a write to any other file is not matched; an absolute path to the repository root (`/repo/.gitignore`) is not matched. The check is a command-form match, so no judge is needed.

Limitation: the pattern anchors with `^` and assumes the engine sets no multiline flag; that is unconfirmed. It also assumes compact `"command":"` JSON (no space after the colon) and needs an engine that supports negative lookbehind and lookahead; that is unconfirmed too. It does not check that the write succeeded.
