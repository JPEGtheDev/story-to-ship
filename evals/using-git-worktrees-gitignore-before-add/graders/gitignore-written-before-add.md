---
type: regex
pattern: '^(?:(?!"command":"(?:[^"\\\n]|\\.)*worktree add)[\s\S])*"command":"(?=(?:[^"\\\n]|\\.)*\.worktrees)(?:[^"\\\n]|\\.)*(?:>>?\s*(?:\\"[^"\\]*|''[^'']*|[^\s"\\'']*)(?<![^\s"''=>|&;])\.gitignore(?![\w.-])|\btee\b\s+(?:(?:-\w+|--[\w-]+)\s+)*(?:\\"[^"\\]*|''[^'']*|[^\s"\\'';|&]*)(?<![^\s"''=>|&;])\.gitignore(?![\w.-])|\bsed\s+-i(?:[^"\\\n]|\\.)*(?<![^\s"''=>|&;])\.gitignore(?![\w.-]))(?:[^"\\\n]|\\.)*"[\s\S]*?"command":"(?:[^"\\\n]|\\.)*worktree add'
match: contains
target: trace
---

Behavior: the run writes `.worktrees` into the repository-root `.gitignore` with a Bash write (a `>` or `>>` redirect; `tee`, after any short (`-a`) or long (`--append`) option; or `sed -i`) in one command that also names `.worktrees`, and that command is run before the first `git worktree add` command. The written file must be `.gitignore` itself: it must start the command or follow whitespace, a quote, `=`, `>`, `|`, `&`, or `;`. A `.gitignore` with any other character directly before it (`.worktrees/.gitignore`, `/tmp/x/.gitignore`, `$(git rev-parse --show-toplevel)/.gitignore`, `a.gitignore`) does not match, and neither does one followed by more name characters (`.gitignore.bak`), so that run fails. A command that only reads `.gitignore` (grep, cat), only runs `git check-ignore`, or only redirects stderr (`2>&1`) does not match, so it fails, even when the skill's own check line prints the instruction. Limits: a write chained with the first `worktree add` in one command is not matched, so that run fails, but the same chained command followed by any later `worktree add` command does match; an edit made with a tool other than Bash is not matched (the case allows only Bash for this step); a write to any other file is not matched. The check is a command-form match, so no judge is needed.

Limitation: the pattern anchors with `^` and assumes the engine sets no multiline flag; that is unconfirmed. It also assumes compact `"command":"` JSON (no space after the colon), its `sed -i` branch accepts `.gitignore` as a whole token anywhere after `sed -i`, and it needs an engine that supports negative lookbehind and lookahead; that is unconfirmed too.
