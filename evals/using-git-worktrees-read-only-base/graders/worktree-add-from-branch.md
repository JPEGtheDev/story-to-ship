type: tool_used
tool: Bash
input_match: '"command"\s*:\s*"(?:[^"\\]|\\.)*?worktree\s+add\b(?:[^"\\\n;&|]|\\")*?\s(?:\\"|'')?agent/row-export(?:\\"|'')?(?=(?:\s+\d?>&?\s*\S+)*\s*(?:\\n|"|&&|;|\|))'
min: 1
---

Behavior: per the rule for a read-only agent, the base is the commit it inspects, so a reviewer for branch agent/row-export gets a worktree created from that branch. The check passes when a Bash `git worktree add` command names agent/row-export as its last argument: an optional quote around it, then any redirects (`2>&1`, `2>/dev/null`, `> file`), then the end of the command value, a chain operator, or a line break. A chained add, a quoted name and an add with redirects pass. A `worktree add` that ends with main or with the remote-tracking name origin/agent/row-export fails this grader (origin/agent/row-export is rejected on purpose: the base must be the local branch). A `worktree add` that names agent/row-export as the new -b branch and then a base after it fails; one that ends with `-b agent/row-export` and no base passes, because the name is then the last argument. The check is a command-form match, so no judge is needed. It proves only that the add names the branch as its last argument; it does not prove that a reviewer agent used that worktree, or that the add succeeded. A path-only command (`git worktree add agent/row-export`) passes, although git then creates a new branch named row-export from HEAD, so the base is wrong and the run counts as a pass. A form that names a commit SHA as the base is missed. The grader does not check the path or the order. A command that only prints the add (`echo git worktree add ... agent/row-export`) also passes, because the pattern matches the command text and does not check that git runs it.
