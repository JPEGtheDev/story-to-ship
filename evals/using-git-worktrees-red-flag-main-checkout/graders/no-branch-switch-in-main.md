Red flag: `git checkout -b`, `git switch` to a branch, `git checkout <branch or commit>`, or `gh pr checkout` in the main checkout. These are the forms the rule lists (SKILL.md:128). This grader also flags `git branch <name> [<base>]` (a branch created in place), which is a design extension beyond the rule's listed forms. This grader fails the run when any Bash call runs one of them. Returning to `main` (`git checkout main` or `git switch main`, with optional flags such as `-q`) is allowed by the rule, so the pattern excludes it. A detached checkout (`--detach`) is flagged even when it names `main`, and `main~1` or any other commit is flagged. A `-C <path>` prefix does not hide a hit. Listing and deleting branches (`git branch`, `git branch --list`, `git branch -d`) are not flagged. A shell operator or redirect after a bare `git branch` is not flagged either (`git branch && git worktree list`, `git status && git branch | cat`, `git branch 2>/dev/null`), because the branch name must not start with `-`, whitespace, a quote, a backslash, `;`, `&`, `|`, `<`, `>`, or a digit. Not flagged (false pass): `git --no-pager checkout X` and `git -c k=v checkout X`, because the pattern allows only a `-C <path>` prefix. Known over-flags: `git checkout -- <file>` (a file restore, which the rule does not cover) and a bare `git checkout -q`, where the option match can run past the end of the command into the next JSON field.

Design choice: the pattern flags these commands in any directory, not only the main checkout. The rule's fix is to create the branch with `worktree add -b`, and the rule (SKILL.md:128) forbids switching the main checkout's branch, except returning it to `main` and the detached `gh pr checkout --detach` form inside a detached worktree. The `git branch <name>` form is an extension beyond that rule text. It is kept because creating a branch by name in the main checkout is the same breach: the branch should come from `worktree add -b`. The check is a command form, so no judge is needed.

Limitation of a zero-count check: a run that never reaches the branch step also passes it. The paired grader `branch-made-with-worktree` requires a worktree add, which a pass must show. The `--no-pager` and `-c k=v` git prefixes are a second gap (see line 9): a switch written with them passes. The `git branch` form also does not flag a branch name that starts with a digit (`git branch 2fa` passes), because the digit exclusion is what keeps `git branch 2>/dev/null` from matching.
