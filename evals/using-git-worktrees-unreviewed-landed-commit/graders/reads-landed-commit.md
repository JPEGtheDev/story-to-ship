---
type: tool_used
tool: Bash
input_match: '\bgit\b(?:\s+-\S+(?:\s+\S+)?)*?\s+show(?![-\w])(?![^;&|\n]*\s(?:--(?:no-patch|quiet)|-[a-zA-Z]*[sq][a-zA-Z]*)(?![\w-]))(?!(?![^;&|\n]*\s(?:-p|--patch)(?![\w-]))[^;&|\n]*\s--(?:stat|name-only|numstat|shortstat|name-status|summary|compact-summary|dirstat)\b)(?!\s+(?:-\S+\s+)*[^\s-]\S*:)'
min: 1
---

Behavior: the run reads a commit with `git show`, with or without global options before it (`git -C <path> show`, `git --no-pager show`, `git -c k=v show`). `git show-ref` and `git show-branch` do not count. A `git show` with `-s`, `--no-patch`, `-q`, `--quiet`, `--stat`, `--name-only`, `--numstat`, `--shortstat`, `--name-status`, `--summary`, `--compact-summary` or `--dirstat` in the same command segment (up to `;`, `&`, `|` or a newline) prints no patch and is not matched. A bundle of short flags that contains `s` or `q` (`-sq`) counts as `-s` or `-q` and is not matched. A `-p` or `--patch` in the same segment overrides only the stat-family flags: `git show -p --stat HEAD` prints the patch and is matched. `--oneline` still prints the patch and is matched. A `<ref>:<path>` first argument (`git show HEAD:plan.md`) reads a file, not the commit, and is not matched. The check is a command form, so no judge is needed. Limits: this grader checks that a read ran, not that it ran before the revert; the paired grader review-before-revert checks the order. A `<ref>:<path>` argument after a commit ref (`git show HEAD HEAD:plan.md`), and a quoted path with a space after `-C` (`git -C "/a b" show`), are not handled. The no-patch exclusion covers only the flags named above: `--raw` and `--check` also print no patch but are still matched, so such a run passes.
