---
type: regex
pattern: '^(?:(?!"command":"(?:[^"\\\n]|\\.)*\b(?:revert|reset|checkout|branch\s+-[dD]|rebase\b(?:[^"\\\n]|\\.)*--onto|restore\b(?:[^"\\\n]|\\.)*(?:--source|\bcommit\b)|commit\b(?:[^"\\\n]|\\.)*--amend)\b)[\s\S])*"command":"(?!(?:[^"\\\n]|\\.)*\b(?:revert|reset|checkout|branch\s+-[dD]|rebase\b(?:[^"\\\n]|\\.)*--onto|restore\b(?:[^"\\\n]|\\.)*(?:--source|\bcommit\b)|commit\b(?:[^"\\\n]|\\.)*--amend)\b)(?:[^"\\\n]|\\.)*\bgit\b(?:\s+-\S+(?:\s+\S+)?)*?\s+show(?![-\w])(?![^;&|\n"\\]*(?:\\(?!n).[^;&|\n"\\]*)*\s(?:--(?:no-patch|quiet)|-[a-zA-Z]*[sq][a-zA-Z]*)(?![\w-]))'
match: contains
target: trace
---

Behavior: the run reads the landed commit with a `git show` command, in some Bash command before any undo command. The undo commands are `git revert`, `git reset`, `git checkout`, `git branch -d` or `-D`, `git rebase` with `--onto`, `git restore` with `--source` or chained with a `git commit`, and `git commit --amend`. The pattern is escape-aware, so `git -C \"/path\" show`, `git --no-pager show` and `git -c k=v show` are matched. `show-ref` and `show-branch` are not matched. A command that also holds an undo command (for example `git revert abc && git show abc`) is not matched, so that run fails. The check is a command-form match, so no judge is needed. Limits: the grader does not check what the run decides after the read, and a `git show` run inside a dispatched subagent may not appear in the trace. A multi-line Bash command is stored with the two characters `\n` for each newline, so `\bgit\b` does not match after one and a correct run in that form fails (false fail). A stat or file form (`git show --stat HEAD`, `git show HEAD:plan.md`) still passes, unlike in the paired grader reads-landed-commit. The no-patch forms `git show -s HEAD`, `git show -q HEAD`, `git show -qs HEAD` (any short-flag bundle with `s` or `q`; git rejects `-sq`) and `git show --no-patch HEAD` do not count as a read, so a run that reads only with them fails. The order check assumes `^` matches only at the start of the whole trace; the engine flags are unconfirmed. A force push, `git switch` or an undo run by a subagent before the read passes. A quoted path with a space (`git -C \"/a b\" show`) is not matched. The no-patch scan stops at the stored two-character `\n`, so a later line with `-s` does not suppress a match. These forms print the patch but are not matched (false fail, safe direction): `-p` or `--patch` with `-q` or `--quiet` in either order, `-s` or `--no-patch` before `-p` or `--patch`, and the bundles `-sp` and `-qp`. `-p` or `--patch` before `-s` or `--no-patch` prints no patch, so not matching it is correct.
